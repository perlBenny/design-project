# 7. CI and workflow

## Workflow

1. Every task is a GitHub issue on the [project board](https://github.com/users/perlBenny/projects/1).
2. Work happens on a `feature/*` branch.
3. One PR per issue, with "Closes" and the issue number in the body.
4. `main` is protected: merge only through a PR, and only when the required checks are green.

## The checks

| Check   | Workflow                                  | What it proves                                                              |
| ------- | ----------------------------------------- | --------------------------------------------------------------------------- |
| `check` | [ci.yml](../.github/workflows/ci.yml)     | Install, lint, format, typecheck and tests pass                             |
| `infra` | [ci.yml](../.github/workflows/ci.yml)     | Docker services start healthy; migrations, rollback, seed and DB tests work |
| `docs`  | [docs.yml](../.github/workflows/docs.yml) | If code changed, the book changed too                                       |

## The book rule

**A PR is not done until the book is updated.** The `docs` check fails when a PR changes files
outside `docs/` but nothing inside it. Changes to `pnpm-lock.yaml` and `db/schema.sql` alone don't count.

If a change truly has nothing to explain (a typo, a version bump), add the **`no-docs`** label.
The check runs again on label changes.

## AI in the workflow

- [`.github/copilot-instructions.md`](../.github/copilot-instructions.md): the rules every AI agent reads.
- [`.github/skills/docs-book/SKILL.md`](../.github/skills/docs-book/SKILL.md): how to update this book.

The skill writes the book; the CI check makes sure nobody forgets. More skills will be added
when a task repeats (for example, writing a migration).
